# Description

One paragraph stating what the PR delivers and why.

A reviewer should understand the scope without opening the ticket. That is the test for whether this section is done — not length. Name the thing that was built and the surface it lands on, and put design or Figma links inline where they are relevant rather than collecting them at the end.

This is the only section on every PR regardless of the work involved, so it carries the summary weight when the rest of the body is short.

The metadata fields — the ticket link and the CI-filled preview blocks — sit under this paragraph as bold labels. Each is its own section with its own guidance.

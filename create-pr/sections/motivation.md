# Motivation

Why the change was needed.

When a ticket exists, this is its Background adapted for a reviewer rather than
copied. The ticket argues that work *should* happen; the PR explains the pressure
the finished work was responding to. Same facts, different tense and audience.

Keep it to the constraints that shaped the result. A reviewer reads Motivation to know which trade-offs were forced and which were chosen — if a bullet doesn't help them judge the diff, it belongs on the ticket when there is one, instead.

Skip this section when the type already carries the reason. A dependency bump does not need a paragraph explaining that dependencies go out of date.
